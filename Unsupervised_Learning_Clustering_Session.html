Introduction to Unsupervised Learning & Clustering

What happens when nobody tells the algorithm what the "right answer" looks like.

Definition

In Plain English

Unsupervised learning is used when the target variable is absent — the dataset isn't labeled. Its goal is finding hidden patterns within the data by grouping data points into homogeneous groups called clusters, without ever being told what the "correct" grouping is.

Supervised vs Unsupervised — Side by Side

Supervised (Days 1-5)Unsupervised (Today)
DataClearly defined X and Y variablesUnlabeled data — no Y at all
GoalPredict a continuous response (regression) or category (classification)Discover emerging patterns based on similarity
Example techniquesLinear/Logistic Regression, Decision TreesClustering, Association Rules (market basket analysis)
How "correct" is judgedCompare predictions to known labelsMuch harder — no ground truth to compare against
Why This Is Genuinely Harder

Unsupervised learning is much harder and more complex than supervised learning specifically because results are hard to define in the absence of a target variable — there's no "accuracy" to compute, no confusion matrix, no ground truth to check against. The other core challenge is defining the objective function itself: what does "good clustering" even mean, mathematically?

Why Bother? — Real Roles of Clustering

Standalone Insight Tool

  • Understand data distribution before modeling
  • Visualization of clusters can unveil important structure

Preprocessing Step

  • Feed cluster labels into a downstream supervised model
  • Gain insight of data before applying a classification model

Example

🎓 Real Use Cases

Customer segmentation (today's hands-on): group customers by behavior for targeted marketing. Anomaly detection: flag transactions that don't fit any normal cluster as potential fraud. Image compression: reduce millions of pixel colors down to K representative colors. Document clustering: automatically group similar articles or support tickets.

The Core Goal of Any Clustering

Maximize SSB (Between-cluster variation)   |   Minimize SSW (Within-cluster variation)

Group records so that points are similar to one another within the same cluster (homogeneity, low SSW) and dissimilar to objects in other clusters (heterogeneity, high SSB) — every clustering algorithm, however different its mechanics, is chasing this same basic goal.

K-Means Clustering & Distance Metrics

The most popular clustering algorithm — and the different rulers it can use to measure "similar."

Definition

In Plain English

K-Means is a partitioning clustering technique that groups data into K distinct, non-overlapping clusters, aiming to minimize the distance between data points within the same cluster and maximize the distance between different clusters. Developed by James MacQueen in 1967.

Key Terminology

TermMeaning
ClusterA collection of data points grouped together because of similarities between them
CentroidA real or imaginary location representing the center of a cluster
KThe number of centroids (clusters) to find — chosen by you, not learned automatically
MeansThe averaging of data used to find each cluster's centroid

Distance Metrics — How "Similar" Gets Measured

Euclidean: √[(x₁−y₁)² + (x₂−y₂)² + ...]
Manhattan: |x₁−y₁| + |x₂−y₂| + ...
MetricIntuitionBest For
EuclideanStraight-line ("as the crow flies") distanceThe default — most common choice, used by K-Means by default
ManhattanCity-block distance — sum of grid-aligned stepsGrid-like data, high-dimensional data (more robust to outliers)
ChebyshevMaximum single-coordinate difference ("chessboard" distance)When the worst single dimension matters most
MinkowskiA generalized formula — Manhattan and Euclidean are special casesWhen you want to tune between Manhattan (p=1) and Euclidean (p=2)
MahalanobisAccounts for correlation between features via the covariance matrixMultivariate data where features are correlated
Minkowski — The Generalized Formula
D = ( Σ|xᵢ−yᵢ|ᵖ )^(1/p)

When p=1, Minkowski becomes Manhattan distance. When p=2, it becomes Euclidean distance. When p=∞, it becomes Chebyshev distance. One formula, three familiar special cases.

Same P and Q, plugged into the same formula, just changing p: using Δage=15, Δspend=30 from before:

pCalculationResultSame as...
1(15¹+30¹)^(1/1)45Manhattan
2(15²+30²)^(1/2)33.5Euclidean
4(15⁴+30⁴)^(1/4)31.2— getting closer to Chebyshev
∞max(15, 30)30Chebyshev

As p climbs, the result glides smoothly from 45 down toward 30 — Minkowski isn't a fourth, separate distance to memorize, it's the dial that lets you SLIDE between the other three.

🎓 Visual — The Unit Circle Changes Shape as p Changes

Every point drawn on each shape's outline is considered "equally far" from the center. As p grows from 1 to 2 to ∞, that outline smoothly inflates from a diamond, to a circle, to a square — a visual way to see the same "sliding dial" the table above shows numerically.

Mahalanobis — Distance That Understands Correlation

The problem Mahalanobis solves: every metric so far treats each feature as independent — but real features are often correlated (taller people tend to weigh more; higher income tends to come with higher spending). Euclidean distance draws perfect CIRCLES around a point, treating every direction as equally likely. If your data actually forms a diagonal, elliptical cloud, those circles are simply the wrong shape for measuring "how unusual is this point."

D = √[ (x−μ)ᵀ S⁻¹ (x−μ) ]

where μ is the distribution's mean, and S⁻¹ is the inverse of the covariance matrix — this is the piece that "corrects" distance for how features move together.

🎓 Visual — Why a Circle Is the Wrong Shape for Correlated Data

Points A and B might sit at the EXACT SAME Euclidean distance from the center (same dashed-circle radius). But B lies right along the natural diagonal "trend" of the data (unremarkable — plenty of real points sit near there), while A sits far off that trend, in a direction the data almost never goes. Mahalanobis distance would correctly flag A as far more unusual than B — exactly the kind of judgment a plain circle-based distance can't make, and exactly why Mahalanobis is popular for multivariate outlier/anomaly detection.

No Single "Correct" Distance Measure

Euclidean is the most widely used, but all distance measures have their own purpose — one cannot claim only one is always accurate. The right choice depends on your data's structure and what "similar" should actually mean for your problem.

Example

🎓 Worked Example — Same Two Points, Three Different Answers

Two customers: P(Age=30, Spending=50) and Q(Age=45, Spending=20). Δage = 15, Δspending = 30.

Euclidean = √[15² + 30²] = √[225 + 900] = √1125 ≈ 33.5

Manhattan = |15| + |30| = 45

Chebyshev = max(15, 30) = 30

Same two points, three genuinely different numbers — which is exactly why the choice of metric matters.

Visual — How Each Metric Actually "Travels" Between Two Points

All three panels connect the exact same P and Q. Euclidean cuts straight through (shortest possible path). Manhattan is forced to travel along the grid lines, like walking city blocks — it never gets to cut diagonally, so its total is always ≥ Euclidean's. Chebyshev ignores the smaller gap (Age) entirely and reports only the larger one (Spending) — it's measuring "the worst single dimension," not total travel distance.

The K-Means Algorithm — Step by Step

A deceptively simple loop that repeats until the clusters stop changing.

Steps

  1. Initialize: pick K random centroids (either random data points, or random values per variable)
  2. Assign: for each data point, calculate distance to all K centroids, assign it to the nearest one
  3. Update: recompute each centroid as the average (mean) of all points now assigned to it
  4. Repeat steps 2-3 until centroids stop moving (convergence) or a maximum iteration count is reached

Formula — The Objective Being Minimized

WCSS = Σ (for each cluster) Σ (for each point in cluster) ||point − centroid||²

WCSS (Within-Cluster Sum of Squares, also called "inertia") is exactly the quantity K-Means is trying to minimize — the squared distance from every point to its own cluster's centroid, summed across all clusters.

Let's Actually Calculate It — 5 Points, 2 Clusters

In plain words, WCSS asks: "for every single point, how far is it from the center of its OWN cluster? Square that distance, then add up every point's squared distance." A small cluster where points huddle close to their centroid gives a LOW WCSS; a loose, spread-out cluster gives a HIGH WCSS. Here's the full calculation, step by step.

Setup: Cluster A has 3 points, centroid (2, 2). Cluster B has 2 points, centroid (8, 8).

ClusterPointCentroidSquared Distance
A(1, 1)(2, 2)(1−2)² + (1−2)² = 1 + 1 = 2
(3, 3)(2, 2)(3−2)² + (3−2)² = 1 + 1 = 2
(2, 1)(2, 2)(2−2)² + (1−2)² = 0 + 1 = 1
B(7, 9)(8, 8)(7−8)² + (9−8)² = 1 + 1 = 2
(9, 7)(8, 8)(9−8)² + (7−8)² = 1 + 1 = 2

Cluster A's contribution: 2 + 2 + 1 = 5   |   Cluster B's contribution: 2 + 2 = 4

WCSS = 5 + 4 = 9

That single number, 9, summarizes how "tight" this entire clustering solution is. Run K-Means again with a different K, get a different WCSS — smaller is tighter, and comparing WCSS across different K values is exactly what the Elbow Method (next section) plots.

Visual — The Iterative Loop

Python Code

Pythonfrom sklearn.cluster import KMeans kmeans = KMeans(n_clusters=4, init='k-means++', random_state=42, n_init=10) labels = kmeans.fit_predict(scaled_data) print(f"WCSS (inertia): {kmeans.inertia_:.1f}")

Advantages & Disadvantages

Advantages

  • Easy to implement
  • Works great on large-scale data
  • Guarantees convergence
  • Easily assigns new examples

Disadvantages

  • Choosing K is genuinely difficult (next section)
  • Centroid initialization matters a lot — a bad start can converge to a worse solution
  • Only handles numeric data directly

Choosing K — Elbow Method & Silhouette Score

There is no formula that hands you the "correct" K — but there are two well-established heuristics that get you close.

Definition — Elbow Method

In Plain English

The Elbow Method runs K-Means across a range of K values and plots WCSS (inertia) against K. As K increases, WCSS always decreases (more clusters = tighter fit) — but the RATE of decrease slows down sharply at some point, forming an "elbow" bend. That bend is the suggested optimal K.

Definition — Silhouette Score

In Plain English

The Silhouette Score measures how similar a point is to its own cluster (cohesion) compared to the nearest other cluster (separation). It ranges from -1 to +1: near +1 means the point is well-matched to its own cluster and far from neighbors; near 0 means it's right on a cluster boundary; negative means it's likely in the WRONG cluster.

Formula

Silhouette(i) = ( b(i) − a(i) ) / max( a(i), b(i) )

where a(i) = average distance from point i to other points in its OWN cluster, and b(i) = average distance from point i to points in the NEAREST other cluster.

Example — Real Numbers, Customer Segmentation

Visual — Reading Both Charts

A Real, Honest Lesson

Real data rarely produces a textbook-perfect elbow or a sharply peaked silhouette curve. When the methods disagree or show only marginal differences, use domain judgment — a simpler, more interpretable K is often the better business choice over chasing the last 0.01 of silhouette score.

Python Code

Pythonfrom sklearn.metrics import silhouette_score inertias, sil_scores = [], [] for k in range(2, 11): km = KMeans(n_clusters=k, random_state=42, n_init=10) labels = km.fit_predict(scaled_data) inertias.append(km.inertia_) sil_scores.append(silhouette_score(scaled_data, labels))

Introduction to Hierarchical Clustering

A completely different philosophy: build the whole family tree of clusters, then decide afterward how many you want.

Definition

In Plain English

Hierarchical clustering sequentially groups records into clusters based on distances between records and between clusters, producing a tree-like structure called a dendrogram — no need to decide K in advance.

Strengths & Disadvantages

Strengths

  • No assumptions on the number of clusters upfront
  • Any desired number of clusters obtained by "cutting" the dendrogram at the right level
  • May correspond to meaningful taxonomies

Disadvantages

  • Time complexity — not suitable for very large datasets
  • Very sensitive to outliers

K-Means vs Hierarchical — When to Use Which

K-MeansHierarchical
Must specify K upfront?YesNo — decide after seeing the dendrogram
Scales to large data?Yes — efficientNo — O(n²) memory/time, struggles beyond a few thousand rows
OutputFlat cluster assignmentsA full nested hierarchy (dendrogram)
Outlier sensitivityModerateHigh
💼 Business Use Case — Why the Hierarchy Itself Is Valuable

A retailer might discover that "high spenders" splits further into "young high spenders" and "older high spenders" only by looking at the dendrogram's finer branches — a flat K-Means result at K=3 would never reveal that nested relationship. Hierarchical clustering is popular in biology (phylogenetics), document clustering, and image segmentation for exactly this reason.

Agglomerative Clustering, Linkage & Dendrograms

The "bottom-up" way hierarchical clustering actually gets built.

Definition

In Plain English

Agglomerative clustering is a bottom-up approach — it starts with every single data point as its own individual cluster, then iteratively merges the two CLOSEST clusters together, repeating until all points belong to a single cluster.

Steps

  1. Start with each data point as a separate cluster
  2. Identify the two closest clusters
  3. Merge them into one cluster
  4. Repeat steps 2-3 until all points are in a single cluster

Linkage Criteria — How "Distance Between Clusters" Gets Defined

LinkageDefinition
SingleShortest distance between any two points, one from each cluster
CompleteLongest distance between any two points, one from each cluster
AverageAverage distance between every pair of points, one from each cluster
CentroidDistance between the two clusters' mean vectors (centroids)
Ward's MethodMerges the pair that produces the smallest increase in total within-cluster variance

Visual — The Dendrogram

Similar records are joined by lines whose vertical HEIGHT reflects the distance between them — the greater the height, the more dissimilar. Choosing a cutoff distance (the dashed red line) on the y-axis creates a specific set of clusters by "cutting" the tree at that level.

Scaling Before Clustering

MethodEffect
Z-Score (Standardization)Rescales features to mean=0, std=1 — the standard choice for clustering
Min-Max ScalingRescales to a fixed 0-1 range — can suppress the effect of outliers due to a smaller resulting standard deviation
Why Scaling Is Non-Negotiable for Clustering

Both K-Means and Hierarchical Clustering rely entirely on DISTANCE calculations. If one feature (like Income, ranging 0-500,000) isn't scaled against another (like Age, ranging 18-90), the large-scale feature will completely dominate every distance calculation — the algorithm would essentially cluster on Income alone, ignoring Age almost entirely.

Python Code

Pythonfrom scipy.cluster.hierarchy import dendrogram, linkage Z = linkage(scaled_data, method='ward') dendrogram(Z, truncate_mode='lastp', p=15)

Hands-On: Bank Transactions

Where a single missing step — log-transforming skewed data — is the difference between useless and genuinely insightful clusters.

How It Works — Build Order

  1. Clean — drop the 1,290 rows with sentinel DOB "1/1/1800" (a placeholder for missing birthdate, not a real value)
  2. Engineer — derive customer Age from DOB and transaction date
  3. Cluster on RAW features — CustAccountBalance & TransactionAmount, scaled but not transformed
  4. Discover the problem — wildly imbalanced clusters
  5. Fix with log-transform — re-cluster
  6. Elbow + Silhouette on the fixed data — confirm K=3

The Critical Finding

💼 Raw vs Log-Transformed — Real Cluster Sizes

Why this happens: CustAccountBalance ranges from 0 to over 51 MILLION, with a median of only ~18,000 — extreme right-skew. A handful of ultra-high-balance accounts create such enormous raw distances that K-Means essentially just isolates those outliers, ignoring the meaningful variation among the other 99% of ordinary customers entirely.

The Universal Lesson

ALWAYS inspect your feature distributions (histograms, min/max, skewness) before clustering financial or count-based data. Extreme skew is common in money-related columns — log-transformation (np.log1p) is a simple, powerful default fix.

Pro Tips

Habits that separate clustering results you can trust from ones that quietly mislead.

📏 Scaling
Always scale features before clustering — distance-based algorithms will let large-scale features silently dominate otherwise. Z-score (StandardScaler) is the standard default.
📈 Skewed Data
Check feature distributions BEFORE clustering. Heavily skewed financial/count data (account balances, transaction amounts, revenue) should usually be log-transformed first — as today's Bank Transactions example dramatically demonstrated.
🎯 Choosing K
Don't blindly pick argmax(silhouette) — a marginal improvement (e.g., 0.336 vs 0.320) rarely justifies a harder-to-interpret, more complex solution. Combine the Elbow Method, Silhouette Score, AND business judgment.
🎯 Choosing K
If your dataset has a known, real number of natural groups (e.g., product tiers, known customer segments), let that inform your K choice — don't ignore domain knowledge in favor of a purely statistical answer.
🌳 Hierarchical Clustering
Never run Hierarchical Clustering on very large datasets (tens of thousands+ rows) without sampling first — its O(n²) memory and time cost makes it impractical, unlike K-Means.
🌳 Hierarchical Clustering
Ward's linkage is a strong general-purpose default — it tends to produce more balanced, compact clusters than single or complete linkage.
🔢 K-Means Limitations
K-Means only handles numeric data directly — encode categoricals first (one-hot or ordinal), and be aware that one-hot-encoded columns can dilute distance meaningfulness in high dimensions.
🎲 Initialization
Always use init='k-means++' (scikit-learn's default) rather than fully random initialization — it spreads initial centroids out intelligently, reducing the risk of a poor local optimum. Also set n_init=10 or higher to run multiple random starts and keep the best.
✅ Validation
When you have partial ground truth (like the Customer Segmentation dataset's real labels), cross-tabulate your clusters against it as a sanity check — even imperfect alignment tells you the clusters are capturing something real.

Interview Questions

Common questions asked in Data Science / ML interviews on this topic. Click a question to reveal the answer.

Q1. Why is unsupervised learning considered harder than supervised learning? ▾
Without a target variable, there's no ground truth to measure "correctness" against — no accuracy, no confusion matrix. The objective function itself is harder to define (what does "good clustering" mean?), and results require domain judgment to interpret and validate rather than an objective metric.
Q2. Walk through the K-Means algorithm step by step. ▾
First, initialize K centroids (randomly or via k-means++ for smarter spacing). Then repeat two steps until convergence: (1) assign each data point to its nearest centroid based on distance, and (2) update each centroid to be the mean of all points now assigned to it. The algorithm converges when centroid positions stop changing meaningfully between iterations.
Q3. How do you choose the optimal value of K in K-Means? ▾
Two common heuristics: the Elbow Method (plot WCSS/inertia against K, look for where the rate of decrease sharply slows — the "elbow") and the Silhouette Score (measures cohesion vs separation, ranging -1 to 1, choose the K maximizing it). Neither is definitive on its own — real data often shows ambiguous elbows or gently-rising silhouette curves, so domain knowledge and interpretability should also guide the final choice.
Q4. What's the difference between K-Means and Hierarchical Clustering? ▾
K-Means requires specifying K upfront, scales well to large datasets, and produces flat (non-nested) cluster assignments. Hierarchical Clustering builds a full nested tree (dendrogram) without needing K in advance, letting you choose the number of clusters afterward by cutting the tree at a chosen height — but it has O(n²) time/memory complexity, making it impractical for very large datasets, and it's more sensitive to outliers.
Q5. Explain the different linkage criteria in Agglomerative Clustering. ▾
Single linkage uses the SHORTEST distance between any two points across two clusters (can create long, straggly "chain" clusters). Complete linkage uses the LONGEST such distance (tends to create more compact, balanced clusters). Average linkage uses the average distance across all cross-cluster point pairs. Ward's method instead merges whichever pair of clusters causes the smallest increase in total within-cluster variance — often the best general-purpose default.
Q6. Why does feature scaling matter so much for clustering? ▾
Both K-Means and Hierarchical Clustering fundamentally rely on distance calculations between points. If one feature has a much larger numeric range than another (e.g., income in the hundreds of thousands vs age in the tens), that feature will dominate every distance calculation, effectively causing the algorithm to cluster almost entirely on that one feature while ignoring the others.
Q7. What is the Silhouette Score, and how do you interpret its range? ▾
The Silhouette Score for a point compares its average distance to points in its own cluster (cohesion) against its average distance to points in the nearest other cluster (separation), producing a value from -1 to +1. Values near +1 indicate the point is well-matched to its own cluster and far from others; values near 0 indicate it sits near a cluster boundary; negative values suggest the point may actually be in the wrong cluster.
Q8. Why is K-Means sensitive to outliers, and how would you address it? ▾
K-Means centroids are computed as MEANS, which are heavily influenced by extreme values — a few outliers can pull a centroid far from where the bulk of "normal" points actually sit, or cause the algorithm to isolate outliers into their own tiny clusters (exactly what happened with the raw Bank Transactions data). Common fixes include removing or capping outliers, using a robust scaler, log-transforming heavily skewed features, or switching to a more outlier-robust algorithm like K-Medoids (which uses actual data points, not means, as cluster centers).
Q9. What is the "curse of dimensionality" in the context of clustering? ▾
As the number of features (dimensions) grows, distances between points tend to become increasingly similar to one another, making it harder for distance-based algorithms like K-Means to meaningfully distinguish "close" from "far" points. This is especially relevant after one-hot encoding many categorical variables, which can add many sparse, low-information dimensions — dimensionality reduction (like PCA) is often applied before clustering high-dimensional data.
Q10. K-Means found clusters of very different sizes (e.g., 18,000 vs 10 vs 100). Is this a problem? ▾
It's often a red flag, not a genuine finding — as demonstrated with the raw Bank Transactions data, wildly imbalanced cluster sizes frequently indicate the algorithm is being dominated by a small number of extreme outliers rather than discovering meaningful behavioral segments. Investigating feature distributions (checking for skew) and applying an appropriate transformation (like a log-transform) is the standard first response before trusting such a result.
Q11. How would you validate clustering results without any ground-truth labels? ▾
Use internal validation metrics like the Silhouette Score or Davies-Bouldin Index (which don't require labels), visually inspect cluster profiles for business plausibility (do the resulting personas make sense?), check cluster stability by re-running with different random seeds or bootstrap samples, and where any partial ground truth exists (even proxy labels), cross-tabulate clusters against it as a sanity check — as done with the Customer Segmentation dataset's real segment labels.
Q12. Can K-Means handle categorical data directly? ▾
No — K-Means computes means and distances, which aren't meaningfully defined for categorical values. Categorical features must first be encoded (one-hot or ordinal) before clustering, though this can introduce its own issues in high dimensions. For datasets that are predominantly categorical, K-Modes or K-Prototypes (a hybrid for mixed numeric/categorical data) are often better-suited alternatives.
